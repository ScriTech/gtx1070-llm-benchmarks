ScriTech model test board

Tested 27 to 30 October 2026 with llama.cpp and PolyStrata on two NVIDIA GTX 1070 8 GB cards in a Dell Precision Tower 7810 (2× Intel Xeon E5-2650 v3, 128 GB DDR4) running Proxmox VE 9.2. The models ran inside an unprivileged Debian 13 LXC container (8 vCPUs, 32 GB RAM, NVIDIA driver 580.173, CUDA 12.8) with both GPUs passed through. Standalone file: all data is embedded, and it makes no network requests.

Long-context sweep: can it still find the codes?

Each run loads the server at that context, fills about 90% of it, hides three vault codes at 10%, 50% and 90% depth and asks for all three (thinking off). E4B was trained for 128K, so its 192K runs were rejected. The 256K run was done only for Gemma 12B with MTP.

KV cache types at 65K context

Each run loads the server at 65K context and runs a 3-code recall test at about 32K fill. Peak VRAM is the larger of the two cards. For Qwen3.6 35B the KV type barely changes speed. Lowering -ncmoe to 22 or 20 ran out of memory even with q4 KV.
